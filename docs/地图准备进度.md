# 地图准备进度与错误状态

Windows 启动后先显示地图准备界面，再进入地图。原图仍按安装目录内的固定文件名读取，不缩放、裁剪、改色或覆盖。

生产处理器通过回调报告 `scanning`、`checking`、`cached`、`processing`、`validating`、`ready`、`error` 阶段。每个状态包含已完成数量、总数、耗时、当前文件和路径。libvips 子进程运行期间每 250ms 报告一次存活及处理状态。总进度按实际完成原图数量计算；单图未完成时不伪造百分比。

Rust 异步服务通过 `spawn_blocking` 隔离文件处理，通过 `/progress` 提供当前状态，未就绪的 `/catalog` 同时返回进度。异步重试使用 `tokio::time::sleep`，不会堵塞 HTTP 和同步服务的运行线程。子进程输出写入独立文件，避免标准输出管道填满而卡死处理。

前端通过 RxJS `BehaviorSubject` 发布进度、订阅更新界面，每 500ms 查询准备状态。状态处理前后执行 `await delay(0)`，将运行权交还浏览器事件循环；退出页面时取消请求和订阅，避免后台更新已卸载界面。

失败界面完整显示原图路径、处理器路径、退出状态、标准错误、标准输出，以及 `.cache/资源处理记录.txt` 路径。目录不可创建、缺少原图、损坏原图、处理器缺失都通过同一个状态流显示。目录创建失败也保持 HTTP 状态服务在线，不因初始化失败直接关闭应用。修复文件后每 5 秒自动重试，完成后自动进入地图。
