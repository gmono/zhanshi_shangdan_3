# 地图准备进度与错误通知

Windows 启动后显示地图准备界面，完成后进入地图。原图按安装目录内的固定文件名读取，不缩放、裁剪、改色或覆盖。

Rust 处理函数通过闭包 `report: &dyn Fn(Value)` 主动报告扫描、检查、缓存命中、处理、验证、完成和错误状态。每次报告立即发布到资源服务的 `ws://Windows地址:1421/events`，不等待前端定时查询。Windows 本机与连接后的 iOS 控制端使用同一个通知接口。

新连接首先接收当前状态快照，再接收后续更新。快照读取、订阅和状态发布由锁保护，避免连接期间丢失状态。处理完成后，在同一条通知中发送 `ready` 进度与可用地图目录，避免出现进度完成但目录尚不可用的间隙。连接正常时前端不请求 `/progress` 或 `/catalog`；这些 HTTP 接口保留用于诊断和兼容已有检查工具。

前端收到通知直接更新 React 状态，无 RxJS、无 500ms 轮询、无额外的进度发送合并窗口。只有连接失败后才等待 1 秒重新连接；重连时服务端立即发送当前快照。页面退出时关闭连接并取消重连，旧连接消息不能覆盖新连接状态。

Rust 使用 `spawn_blocking` 隔离图片处理。子进程通过阻塞等待退出，再用 Rust channel 立即唤醒处理线程，不使用 try_wait + sleep 轮询进程状态。libvips 尚未退出时，每 250ms 的超时分支补充当前文件及耗时的存活通知；子进程退出会提前唤醒等待，扫描、文件切换、错误等通知不经过这段等待。总进度按实际完成原图数量计算，不伪造单张图片的内部百分比。广播队列有容量限制，慢客户端不会拖住处理线程；无法跟上时关闭连接，由客户端重连取得最新状态。

错误界面完整显示原图路径、处理器路径、退出状态、标准错误、标准输出和 `.cache/资源处理记录.txt` 路径。目录不可创建、缺少原图、损坏原图、处理器缺失均推送错误。修复文件后后台每 5 秒重试处理，这属于故障恢复，不是界面查询进度。
