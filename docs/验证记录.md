## Zoomify 超大图

生成并验证三张同配准程序化展厅方案图。每张 TIFF 原图 16000×9000、432,000,140 字节（约 412 MiB），每张生成 3045 个 256px JPEG 瓦片、7 个缩放级别。Chromium 移动视口端到端验证三图固定相机、卷帘同步、进入单图后缩放，以及本地 Zoomify 瓦片加载：约 45 张可见/邻近瓦片，累计约 497 KB；没有请求 TIFF 原图。程序化示意素材仅用于性能验证，不是真实测绘数据。

在 1440×950 浏览器内验证三层均创建 Canvas，各层成功加载 Zoomify 图块，卷帘有两个拖动手柄，三图没有缩放/平移按钮。演示客户端在视口内请求约 45 张瓦片，没有读取原始 TIFF 文件。单图显示放大、缩小、复位按钮。Tauri 调试保持非全屏。`pnpm tauri info` 确认 Linux WebKitGTK 环境可用。

补充：当前浏览器无 relay 连接时，移动端仍可本地验证地图手势和页面切换。切换普通单图立即发送界面状态，避免 16ms 合并窗口导致大屏延迟切换。

### 发现与修复

十图回归发现快速重复导航时当前大图偶尔被隐藏，仅剩浮动操作栏。浮动栏位于路由容器外，原先在 Ionic 转场尚未完成时仍可发起下一次导航。现跟随原生 `ionNavWillChange`、`ionNavDidChange` 事件暂停导航，保留动画与页面缓存；转场结束后按最新共享页继续同步。本机已准备的导航不再重复作为远端换页发起。修复后原先失败的十图回归与全部上述浏览器场景通过，未取消或削弱原有断言。

测试基础设施也完成两项校正：浏览器临时目录使用项目较短的 `tmp/` 路径；Ionic 坐标操作等待实际转场完成。断线通过仅影响第二个 iOS 的透明 TCP 转发连接执行，原样转发生产服务字节，不伪造协议响应；不把浏览器离线设置当作已建立 WebSocket 必然中断。
