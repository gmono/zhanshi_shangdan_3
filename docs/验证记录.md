# 验证记录

日期：2026-10-19。环境：Linux、Node.js 24、pnpm 10、Chromium 浏览器自动化。

## 已验证

- 生产前端构建成功、TypeScript 检查通过。
- ESLint 通过。
- 五项协议测试通过，覆盖有效状态、错误状态、额外字段、分割线边界及只读权限。
- 实际 WebSocket 连接集成测试通过，覆盖房间隔离、共享快照、多控制端页面局部补丁合并、非法状态拒绝、展示端只读和重连恢复。
- 浏览器两窗口联动：控制端用键盘把第一条分割线调至 35%，1920×1080 展示端跟随至 35%。
- 控制端缩放到 13 级，展示端更新至 13 级。
- 从三图主屏进入普通地图，展示端切换；点击返回、浏览器后退均回到三图主屏。
- 展示端不渲染交互分割线和缩放控件。
- 390×844 触摸模拟：单指拖动改变地图中心并经 WebSocket 同步。
- 双指缩放从 12 级变为约 13.415 级。
- 触摸拖动第一条分割线从 33% 变为 43%。
- 手机布局内容宽度 390px，无横向溢出；地图及大屏截图已人工检查。
- 实际地图源返回图像：OSM、Esri 地形、Esri 卫星。移除了返回 API Key 占位图的底图源。

## 验证范围

浏览器模拟不代表 iOS 原生真机手感、内存或长时间稳定性测试。Windows 原生安装包与 iOS 签名包需要各自平台构建；未声称已完成。Zoomify 需要实际预切片图像进行正式性能验证。相机与分割线在操作过程中持续同步，按 16ms 间隔合并发送并保留最终状态。

## 原生基础配置检查

`cargo check --manifest-path src-tauri/Cargo.toml --locked` 在当前 Linux 环境通过，包含稳定版 Tauri 2、平台插件与权限配置。该检查不等同于 Windows / iOS 目标系统打包。

同房间页面重载重新连接成功；通过实际连接设置表单保存新房间后重新连接成功，无页面错误。

补充验证：在手指尚未抬起时，展示订阅已收到平移与双指缩放状态，确认同步发生于操作过程中。卷帘与相机状态按同一节流通道发送。

## 浏览器界面切换复测

配置本机预览中继后，用同一房间的两台浏览器控制端和一台浏览器展示端复测：任一控制端进入普通地图时其他控制端和展示端同步切换；不同控制端分别修改地图相机或地点内层分割线后，未修改的页面字段仍保留；刷新展示端仍恢复最新快照；任一控制端返回三图主屏时展示端同步返回。母线不区分发送端身份，按到达顺序应用最后一次字段写入。

## Windows 底座中继

新增 `src-tauri/src/relay.rs`，由 Tauri Windows 进程监听 `0.0.0.0:8787`，控制端先发送 `hello`，随后发送与 Node 中继相同的状态快照。Windows 展示端通过 `127.0.0.1:8787` 连接自身底座，iOS/浏览器控制端通过 Windows 局域网 IPv4 直连。Linux 当前仅进行源码与依赖检查，Windows 原生防火墙和跨设备实机连接仍需在目标现场验收。

## Zoomify 超大图

生成并验证三张同配准程序化展厅方案图。每张 TIFF 原图 16000×9000、432,000,140 字节（约 412 MiB），每张生成 3045 个 256px JPEG 瓦片、7 个缩放级别。Chromium 移动视口端到端验证三图固定相机、卷帘同步、进入单图后缩放，以及本地 Zoomify 瓦片加载：约 45 张可见/邻近瓦片，累计约 497 KB；没有请求 TIFF 原图。程序化示意素材仅用于性能验证，不是真实测绘数据。

在 1440×950 浏览器内验证三层均创建 Canvas，各层成功加载 Zoomify 图块，卷帘有两个拖动手柄，三图没有缩放/平移按钮。演示客户端在视口内请求约 45 张瓦片，没有读取原始 TIFF 文件。单图显示放大、缩小、复位按钮。Tauri 调试保持非全屏。`pnpm tauri info` 确认 Linux WebKitGTK 环境可用。

补充：当前浏览器无 relay 连接时，移动端仍可本地验证地图手势和页面切换。切换普通单图立即发送界面状态，避免 16ms 合并窗口导致大屏延迟切换。

## Windows 展示端置顶

Windows 启动路径设置 Tauri 全屏与 always-on-top，并调用 Win32 `SetWindowPos(HWND_TOPMOST)`；手动全屏切换复用该路径，退出时恢复普通层级。Linux setup 按 cfg 不自动全屏，保留窗口调试。`cargo check --target x86_64-pc-windows-gnu --locked` 和 Linux `cargo check --locked` 均通过；未在 Windows 桌面实机验证实际 Z 序。
