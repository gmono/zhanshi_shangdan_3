# 原图版本一致性修复与验证

修复目标：原图文件名（含扩展名）、字节数或修改时间任一变化时，前端瓦片版本与后端缓存失效判定保持一致。继续使用元数据，不读取巨图内容计算版本哈希。

- 先增加 Rust 回归：重命名图片后，大小和修改时间均不变，版本仍须变化；确认旧实现失败。
- 将文件名纳入版本号，保留前端已有瓦片版本参数和地图重建逻辑。
- 用真实 Rust 服务、libvips 和双浏览器验证同尺寸、同字节数的同名替换，以及同字节数、同时间的跨扩展名替换。保留浏览器及缓存，通过画布像素和原图哈希验收。
- Windows CI 与 macOS WebKit CI 执行该回归，同时继续运行 Windows 安装后联测、原生 iPad 连接测试和 IPA 构建。
- 测试入口先完成真实同步握手再启动浏览器测试，避免 Windows 首次启动未监听时抢跑。
- 原图契约测试按阶段最多等待120秒，单次请求最多2秒；超时保留目标地址、最后进度和子进程退出信息，CI 保存失败报告，不能再将所有等待失败折叠成无上下文的一句错误。
- 全量测试发现缩放回声浮点误差：客户端发送 `0.11093818700579439`，Rust 回传 `0.1109381870057944`，严格比较误判并取消动画。增加回归并使用数个浮点末位的容差；继续验证其他控制端的实际变更可正常应用。
- 验证通过后提交推送。双端构建均使用最终提交，IPA 仅本地签名；执行 `pnpm artifacts:collect` 更新 `out/`。
