# 同步消息顺序

房间中的 Windows 触摸展示端与所有 iOS 共用一份全局状态。Windows 仍提供同步及资源服务，本机前端通过 `127.0.0.1:8787` 连接同一母线。母线不选主控端，两种角色具有相同的状态发布权限；任一端的操作都进入同一条 WebSocket 状态通道，母线按消息到达顺序应用。不同页面或地点的补丁只改指定字段，不把某一端缓存的整份旧状态写回去。

每条状态写入都带 `pageId` 和整数 `id`。单图相机补丁的 `pageId` 为 `map-1`～`map-10`，只合并该图的 `mapViews[pageId]`；主页内层分割线补丁的 `pageId` 为 `comparison`，并以地点索引为键只更新对应 `innerSplits`。页面跳转同时写入全局 `page` 与目标页编号；谁最后操作页面，其余各端就跟随谁操作的页面。无关页面相机、其他地点分割线和其余全局字段均保留。

Windows 不增加任何操作按钮或指示器。主页仅开放已有内层分割线整条线附近的触摸命中区，一级地点保持三等分；单图开放已有触摸缩放和平移，操作也按 16ms 窗口合并发送。地图更新抑制逻辑适用于两种角色：应用远端相机或适配窗口不发布消息，本机相机回声不打断当前手势。

点击自动发现的图 1～10 时，控制端先发送一条带目标 `pageId` 的页面补丁，包含 `page` 与该图的初始 `mapViews`，然后执行本地导航。按钮按 Windows 资源目录实际数量生成。不拆成换页、复位两条消息，不依赖延时或动画结束通知。返回主页是明确的全局复位操作，发送带 `pageId: "comparison"` 的完整替换状态：一级分栏均分、二级线归零并清空单图操作视角。

母线在同一临界区内合并局部补丁、增加房间 `revision` 并排队广播完整快照。其他控制端和展示端接收快照；发送端接收带 `sourceId` 的 `state_ack` 确认并据此收敛本地状态。母线不会把发送端身份作为控制权或状态优先级条件。同一字段按母线接收顺序最后写入者生效。

Windows 与 iOS 都在收到其他端快照时重放本机尚未确认的字段级补丁，避免当前操作被旧快照短暂覆盖；收到确认后移除相应在途补丁并采纳合并状态。旧 `revision` 的快照或确认不能回退已接收的新状态，接收消息本身不会触发状态发布。

iOS 路由跟随共享 `page`，由远端引起的路由变化不调用进入页复位，也不回传第二条换页消息。首次连接已有房间及资源目录到达时不发布主页复位，防止后连接的 iOS 改掉现有画面。设置页只影响当前 iOS，退出设置后对齐共享页面。主动按钮导航、Ionic 返回手势和浏览器返回仍按现有规则先准备状态、再完成页面切换。

单图的 `mapViews` 使用 `space: "image-relative"`：`center` 为图片内中心比例，`zoom` 为相对完整显示的放大级数。初始消息固定为中心 `[0.5, 0.5]`、放大 `0`。两端收到后，各自根据图片和当前画布的宽高计算本机分辨率；同步消息不携带控制端的窗口宽高或像素缩放。窗口改变时，本机重新适配，保持相同的图片中心与相对放大级数。图片比例和屏幕比例不同时，完整显示会在一个方向留边，不拉伸或裁掉原图。协议仍兼容没有 `space` 的旧视角字段。

Windows 的 Rust 母线在同一个锁内合并状态补丁、分配编号并入队广播。展示端以一份完整状态更新页面和视角；地图挂载显示目标前应用视角，首次显示前同步刷新缓存画布。隐藏的缓存单图不发布操作，程序应用视角和窗口适配不会反向触发状态回写。

返回主页同样先发送一条完整复位状态，再执行返回路由：页码为 `comparison`、一级分栏固定均分、二级线全为 `0`、清空单图操作视角。保留 Ionic 原有转场；地图页的 `WillLeave` 通过 ref 设 `display:none`，`WillEnter` 恢复显示。操作面板只在路由容器外保留一个节点，通过路由信号切换内容。

不同分辨率测试包括 `1194×834 → 3840×2160` 和 `1024×1366 → 1920×1080`。测试同时连接真实 Rust 母线，用画布像素检查初始图片适配比例，验证缩放、拖动，以及修改二级线后返回主页的首条复位消息和两端显示状态。二级对比资源按文件编号 `[1, 2]` 排列，1 对应左侧、2 对应右侧；分割线为 0 时左侧宽度为零，向右拖动逐渐展开左图。图片年份由实际原图决定，不从编号推断。

每条应用层同步消息均有正整数 `id` 和 `pageId`：控制端的 `hello`、`state`、`heartbeat`，以及母线的 `snapshot`、`state_ack`、`presence`、`error`、`heartbeat_ack`。`pageId` 指出该消息关联的地图页；心跳和连接状态消息使用当前全局页。编号在各自发送端的生命周期内递增；母线重启后编号可以重新开始，不能跨服务重启仅凭编号判定消息新旧。WebSocket 控制帧不属于应用层消息。

各端重新连接保留本实例的编号计数。母线为下行消息独立分配 `id`，用 `sourceId` 关联状态确认与触发该次写入的消息，`revision` 表示房间状态版本。状态快照按 `revision` 顺序应用，低于已应用版本的快照丢弃。母线重启后 `revision` 与下行编号可以重新开始；连接建立后从新快照重新同步。首次连接或重连已有房间时清除旧在途和待发送补丁，只采用服务器状态；仅空房间允许发送完整初始状态。单个 iOS 断开不会清空服务器状态，Windows 和其他在线 iOS 继续操作及同步。

各端每5秒发送 `heartbeat`，携带自己的正整数 `id`。母线回 `heartbeat_ack`，通过 `sourceId` 确认该请求，并为应答分配新的母线 `id`。该消息不写入地图状态、不增加地图 revision，也不推送视角变化。收到匹配应答后清除本轮超时；连续15秒无应答时该端关闭 socket 并重连。Rust 与 Node 母线每5秒发送 WebSocket 控制 Ping；Node 在15秒无 Pong 后清理连接，Rust 在下一轮检查中清理，最迟约20秒。Node 房间最多16个连接；两种母线均允许多个控制端和展示端平等写入。旧版服务仍可能返回“已有控制端”，客户端保留重试兼容逻辑，但新母线不使用控制端独占名额。
