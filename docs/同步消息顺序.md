# 同步消息顺序

点击图 1～5 时，控制端先按图片尺寸和显示区域同步计算初始视角，再发送完整 `state`，最后执行本地导航。`page`、`center`、`zoom` 和对应 `mapViews` 在同一消息中提交，不拆成换页、复位两条消息，不依赖延时或动画结束通知。

Windows 的 Rust 母线在同一个锁内保存完整状态、分配编号并入队广播。展示端以一份状态更新页面和视角；地图挂载显示目标前应用视角，首次显示前同步刷新缓存画布。单图不再根据 Windows 窗口大小另行修正收到的缩放。

每条应用层同步消息均有正整数 `id`：控制端的 `hello`、`state`，以及母线的 `snapshot`、`presence`、`error`。编号在各自发送端的生命周期内递增；母线重启后编号可以重新开始，不能跨服务重启仅凭编号判定消息新旧。WebSocket 控制帧不属于应用层消息。

控制端重新连接保留本实例的编号计数。母线为下行消息独立分配 `id`，并在状态广播中用 `sourceId` 保留控制端原始编号，`revision` 表示房间状态版本。当前只补齐编号与关联信息，不新增丢包、过期消息丢弃策略。旧客户端缺少 `id` 仍可接入，新的发送端均携带编号。
